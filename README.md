# Car Launcher

Автомобильный лаунчер (Flutter) для Android-магнитолы. Экран: слева док
с часами и ярлыками приложений, справа три окна — в каждом настоящее
установленное приложение (навигатор, музыка и т.д.). Плюс роль лаунчера
по умолчанию и опциональный киоск-режим через Device Owner.

Приложения в трёх окнах показываются одним из двух способов, лаунчер
выбирает сам:

- **Живые окна (системный режим), как в CarCar.** APK подписан
  платформенным ключом (в CI — публичным тестовым ключом AOSP) и имеет
  `sharedUserId=android.uid.system`. На прошивках, которые доверяют
  этому ключу (многие китайские магнитолы — на такой у пользователя
  работает CarCar), лаунчер становится системным приложением и через
  `android.app.ActivityView` встраивает живое, реагирующее на касания
  окно чужого приложения прямо в свою область. Это единственный способ
  показать именно «живое» окно внутри лаунчера — и доступен он только
  системному приложению.
- **Свободные окна (freeform), запасной вариант.** Если прошивка ключу
  не доверяет (обычный телефон/эмулятор/планшет), APK ставится как
  обычное приложение, ActivityView недоступен, и лаунчер просто
  запускает приложения свободными окнами в заданных координатах — если
  устройство поддерживает freeform.

## Как пользоваться

- **Окна.** Нажмите на окно, чтобы выбрать для него приложение;
  дальше нажатие открывает это приложение окном в этой области.
  Удержание — сменить приложение или очистить окно.
  Кнопка «Разложить окна» открывает все три сразу; при запуске
  лаунчера это происходит автоматически (если свободные окна доступны).
- **Док.** Ярлыки слева: нажатие — запустить приложение на весь экран,
  удержание — выбрать другое.
- Выбор приложений сохраняется и переживает перезагрузку.

## Как это работает внутри

**Живые окна.** `AppWindowHost.kt` через рефлексию создаёт
`android.app.ActivityView` (скрытый системный класс, есть на
Android 10/11, удалён в 12+), кладёт их в прозрачный оверлей поверх
FlutterView в координатах, которые присылает Flutter, и запускает в
каждом нужное приложение. Flutter рисует док и подложки, живые окна —
нативные View сверху. Это работает, только если `isSystemApp()` вернул
true (APK установлен как системный) и класс ActivityView доступен;
иначе лаунчер молча переходит на свободные окна. В системном режиме
живое окно перехватывает касания, поэтому для смены приложения в окне
есть кнопка «Изменить окна» — она временно убирает живые окна и
открывает карточки выбора.

**Свободные окна (запасной режим).** `ActivityOptions.setLaunchBounds`
просит систему открыть приложение окном в заданных координатах.
Работает только при поддержке freeform; лаунчер проверяет это и, если
поддержки нет, показывает инструкцию: «Для разработчиков» → «Окна
произвольной формы» + «Изменение размера в многооконном режиме» →
перезагрузка.

Что проверяется только на самой магнитоле: доверяет ли прошивка ключу
AOSP (ставится ли APK системным), создаёт ли ActivityView окна без
системной рамки, как ведут себя окна при уходе лаунчера в фон.

## Платформенная подпись

APK переподписывается в CI публичным тестовым ключом AOSP
(`platform.pk8` / `platform.x509.pem` из `aosp-mirror/platform_build`)
через `apksigner`. Ключ открытый и одинаковый у многих китайских
прошивок — именно поэтому подписанное им приложение получает на такой
магнитоле системные права. На устройстве с собственным ключом
производителя такой APK не установится; это ограничение самой модели
безопасности Android, обойти его из обычного приложения нельзя.

## Сборка — автоматически, через GitHub Actions

При каждом push в `main` (а также вручную — вкладка **Actions** →
**Build Android APK** → **Run workflow**) собирается release APK и
публикуется как GitHub Release `build-N`.

Workflow (`.github/workflows/build-apk.yml`): ставит Flutter на сервере
GitHub, генерирует свежий Android-скаффолд (`flutter create`),
накладывает поверх наш код (`lib/`, `android_overlay/`), дописывает
зависимости в `pubspec.yaml` скриптом `scripts/patch_project.py`,
проверяет код `flutter analyze` и собирает APK. При ошибке ключевые
строки лога попадают в аннотации запуска.

## Структура репозитория

```
lib/                          — весь Dart/Flutter-код приложения
android_overlay/
  AndroidManifest.xml          — финальный манифест (роль HOME, receivers)
  kotlin/com/carlauncher/app/  — MainActivity (список приложений, запуск,
                                  запуск в окне, проверка freeform, роль
                                  лаунчера, киоск), BootReceiver,
                                  DeviceOwnerReceiver
  res/xml/device_admin_receiver.xml
pubspec_extra.yaml             — дополнительные зависимости
scripts/patch_project.py       — слияние pubspec, запускается в workflow
.github/workflows/build-apk.yml
```

## Device Owner (киоск-режим) — опционально

```bash
adb shell dpm set-device-owner com.carlauncher.app/.DeviceOwnerReceiver
```

Только на устройстве без добавленных аккаунтов. После этого в настройках
лаунчера появится переключатель киоск-режима.

## Установка APK

Скачайте `car-launcher-build-N.apk` со страницы Releases, разрешите
установку из неизвестных источников и установите. При нажатии «Домой»
выберите Car Launcher лаунчером по умолчанию (или кнопка «Назначить»
в настройках лаунчера). APK подписан debug-ключом — для личного
использования этого достаточно.
